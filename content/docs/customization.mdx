**Customize Unstack Pro to match your brand and product needs.** The template is designed to be extended while keeping the core auth and organization features intact.

<Callout type="info">
You don't need to modify auth code to customize your app. Focus on branding, adding features, and extending the schema.
</Callout>

## Branding

### Site Configuration

Update your app's name, description, and metadata in `/config/site.ts`:

```typescript title="config/site.ts"
export const siteConfig = {
  name: "Your App Name",
  description: "Your app description for SEO and social sharing",
  url: "https://yourdomain.com",
  ogImage: "https://yourdomain.com/og.png",
  links: {
    twitter: "https://twitter.com/yourapp",
    github: "https://github.com/yourorg/yourapp",
  },
};
```

### Logo and Favicon

Replace the default logos:

1. **Favicon**: Replace `/app/favicon.ico`
2. **Logo**: Add your logo to `/public/logo.png` and `/public/logo-dark.png`
3. **Update components** that reference the logo

```tsx title="components/logo.tsx"
import Image from "next/image";

export function Logo() {
  return (
    <>
      <Image
        src="/logo.png"
        alt="Your App"
        width={120}
        height={40}
        className="dark:hidden"
      />
      <Image
        src="/logo-dark.png"
        alt="Your App"
        width={120}
        height={40}
        className="hidden dark:block"
      />
    </>
  );
}
```

### Colors and Theme

Unstack Pro uses Tailwind CSS v4 with CSS variables for theming. Customize colors in `/styles/globals.css`:

```css title="styles/globals.css"
@import "tailwindcss";

@custom-variant dark (&:is(.dark *));

:root {
    color-scheme: light;
    --background: oklch(1 0 0);
    --foreground: oklch(0.145 0 0);
    --primary: oklch(0.546 0.245 262.881);
    --primary-foreground: oklch(0.97 0.014 254.604);
    --border: oklch(0.922 0 0);
    --ring: oklch(0.546 0.245 262.881);
    --radius: 0.625rem;
}

.dark {
    color-scheme: dark;
    --background: oklch(0.145 0 0);
    --foreground: oklch(0.985 0 0);
    --primary: oklch(0.623 0.214 259.815);
    --primary-foreground: oklch(0.97 0.014 254.604);
    --border: oklch(0.269 0 0);
    --ring: oklch(0.623 0.214 259.815);
}

@theme inline {
    --color-background: var(--background);
    --color-foreground: var(--foreground);
    --color-primary: var(--primary);
}
```

Every token is declared on `:root`, overridden in `.dark`, and exposed to Tailwind
through the `@theme inline` block at the bottom of the file. Change a value in
both blocks and the rest of the UI follows.

## Adding OAuth Providers

Better Auth supports many OAuth providers. To add one:

<Steps>

<Step>

### Configure the Provider

Add a `socialProviders` block to the Better Auth options:

```typescript
socialProviders: {
  google: {
    clientId: process.env.GOOGLE_CLIENT_ID!,
    clientSecret: process.env.GOOGLE_CLIENT_SECRET!,
  },
  github: {
    clientId: process.env.GITHUB_CLIENT_ID!,
    clientSecret: process.env.GITHUB_CLIENT_SECRET!,
  },
},
```

<Tabs groupId="edition" persist items={["Postgres", "Convex"]}>

<Tab value="Postgres">

The options are the `betterAuth({ … })` call in `lib/auth.ts`, which runs inside
Next.js on `drizzleAdapter`.

</Tab>

<Tab value="Convex">

The options are `createAuthOptions` in `convex/betterAuth/auth.ts` — Better Auth
runs *inside* Convex, so that file is the source of truth.

</Tab>

</Tabs>

<Callout type="info">
No social providers are configured out of the box — the stack is OAuth-*ready*.
</Callout>

</Step>

<Step>

### Add Environment Variables

The credentials go wherever the auth options are evaluated:

<Tabs groupId="edition" persist items={["Postgres", "Convex"]}>

<Tab value="Postgres">

```dotenv title=".env.local"
GOOGLE_CLIENT_ID="your-google-client-id"
GOOGLE_CLIENT_SECRET="your-google-client-secret"
GITHUB_CLIENT_ID="your-github-client-id"
GITHUB_CLIENT_SECRET="your-github-client-secret"
```

</Tab>

<Tab value="Convex">

These are read in the Convex runtime, so they belong on the Convex deployment
rather than in `.env.local`:

```bash
bunx convex env set GOOGLE_CLIENT_ID "your-google-client-id"
bunx convex env set GOOGLE_CLIENT_SECRET "your-google-client-secret"
bunx convex env set GITHUB_CLIENT_ID "your-github-client-id"
bunx convex env set GITHUB_CLIENT_SECRET "your-github-client-secret"
```

</Tab>

</Tabs>

</Step>

<Step>

### Add Sign-In Button

Add the OAuth button to your login page:

```tsx title="app/auth/login/_components/oauth-buttons.tsx"
"use client";

import { authClient } from "@/lib/auth-client";
import { Button } from "@/components/ui/button";
import { FaGoogle, FaGithub } from "react-icons/fa";

export function OAuthButtons() {
  const signInWithGoogle = async () => {
    await authClient.signIn.social({
      provider: "google",
      callbackURL: "/",
    });
  };

  const signInWithGithub = async () => {
    await authClient.signIn.social({
      provider: "github",
      callbackURL: "/",
    });
  };

  return (
    <div className="grid gap-2">
      <Button variant="outline" onClick={signInWithGoogle}>
        <FaGoogle className="mr-2 h-4 w-4" />
        Continue with Google
      </Button>
      <Button variant="outline" onClick={signInWithGithub}>
        <FaGithub className="mr-2 h-4 w-4" />
        Continue with GitHub
      </Button>
    </div>
  );
}
```

</Step>

<Step>

### Configure OAuth App

Set up the OAuth app with the provider:

**Google:**
1. Go to [Google Cloud Console](https://console.cloud.google.com)
2. Create OAuth 2.0 credentials
3. Add authorized redirect URI: `https://yourdomain.com/api/auth/callback/google`

**GitHub:**
1. Go to [GitHub Developer Settings](https://github.com/settings/developers)
2. Create new OAuth App
3. Set callback URL: `https://yourdomain.com/api/auth/callback/github`

</Step>

</Steps>

<Callout type="info">
For a full list of supported providers, see the [Better Auth Social Providers documentation](https://www.better-auth.com/docs/authentication/social).
</Callout>

## Adding New Pages

### Create a New Route

Add pages using Next.js App Router conventions:

```tsx title="app/dashboard/page.tsx"
import { requireSession } from "@/lib/session";

export default async function DashboardPage() {
  const session = await requireSession();

  return (
    <div className="container py-8">
      <h1 className="text-3xl font-bold">Dashboard</h1>
      <p>Welcome, {session.user.name}!</p>
    </div>
  );
}
```

### Protected Routes

Use `requireSession()` to protect routes - it automatically redirects to the login page if the user is not authenticated:

```tsx title="app/dashboard/layout.tsx"
import { requireSession } from "@/lib/session";

export default async function DashboardLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  await requireSession();

  return <>{children}</>;
}
```

### Organization-Scoped Routes

Access organization context in routes:

```tsx title="app/organizations/[organizationSlug]/projects/page.tsx"
import { requireSession } from "@/lib/session";

interface Props {
  params: { organizationSlug: string };
}

export default async function ProjectsPage({ params }: Props) {
  const session = await requireSession();
  const { organizationSlug } = params;

  // Fetch organization-specific data
  // Verify user has access to this organization

  return (
    <div>
      <h1>Projects for {organizationSlug}</h1>
      {/* Your content */}
    </div>
  );
}
```

### Custom Validation Rules

Extend Zod schemas for custom validation:

```typescript title="schemas/auth.ts"
import { z } from "zod";

export const registerSchema = z.object({
  name: z.string().min(2, "Name must be at least 2 characters"),
  email: z.string().email("Invalid email address"),
  password: z
    .string()
    .min(8, "Password must be at least 8 characters")
    .regex(/[A-Z]/, "Password must contain an uppercase letter")
    .regex(/[0-9]/, "Password must contain a number"),
});

export const customProfileSchema = z.object({
  name: z.string().min(2),
  company: z.string().optional(),
  jobTitle: z.string().optional(),
  website: z.string().url().optional(),
});
```

## Removing Optional Features

### Remove Autumn (Billing)

If you don't need billing:

1. Remove `AUTUMN_SECRET_KEY` from environment variables
2. Delete billing-related routes in `/app/organizations/[organizationSlug]/billing/`
3. Remove billing UI components
4. Update organization creation to not require billing

### Remove Sentry (Error Monitoring)

Sentry is **environment-variable driven** — the SDK no-ops when
`NEXT_PUBLIC_SENTRY_DSN` is empty, and builds skip source-map upload when
`SENTRY_AUTH_TOKEN` is missing. To simply disable it, leave those variables unset;
no code changes are required.

To remove it entirely:

1. Delete `instrumentation.ts`, `instrumentation-client.ts`,
   `sentry.edge.config.ts`, and `sentry.server.config.ts`
2. Remove the Sentry wrapper from `next.config.js`
3. Drop the `NEXT_PUBLIC_SENTRY_DSN` / `SENTRY_*` env vars
4. Uninstall the package:

```bash
bun remove @sentry/nextjs
```

### Remove Passkeys

If you don't need passkey authentication:

1. Remove passkey routes in `/app/account/security/passkeys/`
2. Remove passkey components
3. Drop `passkey()` from the `plugins` array in the Better Auth config, and stop
   setting `PASSKEY_RP_ID`

## Reading and Writing Your Own Data

Routes live in `app/` and components in `components/` either way. How a page gets
its data is the part that differs, and it shapes every feature you add:

<Tabs groupId="edition" persist items={["Postgres", "Convex"]}>

<Tab value="Postgres">

There are no live queries. A Server Component reads through a function in
`lib/server/`, a write is a server action in `actions/`, and the client calls
`router.refresh()` afterwards to pull a fresh render.

```typescript title="lib/server/projects.ts"
import "server-only";

import { eq } from "drizzle-orm";
import { db } from "@/lib/db";
import { project } from "@/lib/db/schema";
import { requireSession } from "@/lib/session";

export async function listProjects(organizationId: string) {
  await requireSession();

  return db
    .select()
    .from(project)
    .where(eq(project.organizationId, organizationId));
}
```

```tsx title="app/organizations/[organizationSlug]/projects/_components/new-project.tsx"
"use client";

import { useRouter } from "next/navigation";
import { createProject } from "@/actions/projects";

export function NewProject({ organizationId }: { organizationId: string }) {
  const router = useRouter();

  return (
    <button
      onClick={async () => {
        await createProject({ organizationId });
        router.refresh();
      }}
      type="button"
    >
      New project
    </button>
  );
}
```

</Tab>

<Tab value="Convex">

Queries are reactive. A `useQuery` in a client component re-renders on its own
whenever the data behind it changes, so a mutation needs no follow-up refresh.
Custom hooks go in `lib/hooks/`:

```typescript title="lib/hooks/use-organization.ts"
"use client";

import { useQuery } from "convex/react";
import { api } from "@/convex/_generated/api";

export function useOrganization(slug: string) {
  const organization = useQuery(api.organizations.getBySlug, { slug });
  const members = useQuery(api.organizations.getMembers, { slug });

  return {
    organization,
    members,
    isLoading: organization === undefined,
  };
}
```

</Tab>

</Tabs>

## Legal Pages (Terms & Privacy)

The template ships starter **Terms of Service** and **Privacy Policy** pages so you
have something to link from the footer and the register screen on day one:

```
app/(legal)/
├── layout.tsx          # Shared minimal legal layout
├── terms/page.tsx      # Terms of Service (starter copy)
└── privacy/page.tsx    # Privacy Policy (starter copy)
```

Company/app name and the contact address are parameterized through
`config/site.ts` (`appName`, `supportEmail`), so you mostly edit copy rather than
markup.

<Callout type="error">
The starter copy is a **scaffold, not legal advice**. Before going to production,
review and replace the Terms and Privacy copy with your own (ideally with counsel),
set `NEXT_PUBLIC_SUPPORT_EMAIL` to your real support address, and confirm the listed
data processors and retention/refund terms match your business.
</Callout>

## Demo Video Tooling (Bonus)

The template includes a two-stage pipeline that turns the real app into an edited,
launch-style demo video — a bonus you can use or delete.

```bash
# One-time setup
bun run demo:install-browsers    # Playwright Chromium
cd video && bun install && cd .. # the Remotion project has its own deps
```

Then render, with the app already running:

<Tabs groupId="edition" persist items={["Postgres", "Convex"]}>

<Tab value="Postgres">

```bash
# with `bun dev` running
DEMO_EMAIL=you@example.com DEMO_PASSWORD=your-password bun run demo:render
```

</Tab>

<Tab value="Convex">

```bash
# with `bun convex dev` and `bun dev` both running
DEMO_EMAIL=you@example.com DEMO_PASSWORD=your-password bun run demo:render
```

</Tab>

</Tabs>

- **`bun run demo:capture`** — Playwright drives the app and captures real screens
  into `video/public/demo` (see the header comment in `scripts/capture-demo.ts` for
  the full list of `DEMO_*` env vars).
- **`bun run demo:video`** — renders the Remotion composition in `video/`.
- **`bun run demo:render`** — runs both stages; output is
  `demo-output/unstack-pro-demo-latest.mp4`.

<Callout type="info">
The `video/` Remotion project is a self-contained package with its **own**
dependencies — run `bun install` inside it once before rendering. See the product
README's "Scripted Demo Video" section for details.
</Callout>

## Best Practices

1. **Don't modify core auth files** unless necessary - extend instead
2. **Keep components small** and focused on one responsibility
3. **Use TypeScript strictly** for type safety
4. **Follow existing patterns** for consistency
5. **Test changes locally** before deploying
6. **Document custom code** for future reference
7. **Use environment variables** for all configuration
8. **Keep secrets secure** - never commit them
